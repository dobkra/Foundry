## Classification Rationale

The example concerns a possible future Launcher UI / Foundry Control Center entry point inside the existing Foundry system.

It is treated as a `new_module` initiation example because the work would likely become a module or entry point inside Foundry, not a new independent repository, unless Dobromir later approves a different structure.

This packet does not approve actual module creation. It only demonstrates how a `new_module` initiation packet would be prepared.

## Why This Is Not `new_project`

This is not a `new_project` because it does not start a new independent Foundry project or repository.

The parent context already exists: Foundry / Foundry Launcher.

## Why This Is Not `work_package`

This is not a `work_package` because the example is framed as initiation of a possible future module, not merely a scoped body of work inside an already approved module.

The packet demonstrates how deeper planning would happen before real module approval.

## Why This Is Not `audit`

This is not an `audit` because it does not assess or review an existing project/module.

It prepares a forward-looking initiation example.

## Why This Is Not `decision_workshop`

This is not a `decision_workshop` because it creates a complete staged initiation packet with planning packs and proposed issue breakdown.

It includes decision questions, but the packet is not only conceptual decision work.
