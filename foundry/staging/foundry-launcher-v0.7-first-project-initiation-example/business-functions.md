## Business objective

Reduce friction and copy/paste in project initiation while preserving Foundry approval gates, decision authority, and execution boundaries.

## User roles

- Dobromir.
- ChatGPT.
- Codex.
- Linear.
- GitHub.

## Internal roles

- Dobromir: founder, decision owner, approval authority.
- ChatGPT: planning architect and strategic reasoning layer.
- Codex: repository execution agent after approval.
- Linear: execution/project-management mirror after approval.
- GitHub: source of truth for repository changes and PR history.

## Business workflows

- Idea capture.
- Classification.
- Discovery/architecture planning.
- Review decision.
- Issue breakdown.
- Execution handoff.

## Service model

Foundry acts as the execution factory.

The Launcher acts as the front door that converts loose ideas into structured, reviewable packets before execution setup.

## Commercial logic

No pricing or commercial model is changed by this packet.

## Operational responsibilities

- Dobromir reviews strategic direction and authority decisions.
- ChatGPT helps plan and structure packets.
- Codex records packet files and later executes approved scoped work.
- Linear may mirror approved work only after approval.
- GitHub records code/documentation changes through PRs.

- Raw idea.
- Parent context.
- Classification.

- Approval categories.
- Execution permissions.
- Blocked work.
- Reviewer decision.

## Outputs produced

- Staging packet.
- Planning pack files.
- Review summary.
- Proposed issue breakdown.
- Future Codex prompt only after approval.
