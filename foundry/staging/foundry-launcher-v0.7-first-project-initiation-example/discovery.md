## Raw idea summary

Initiate a realistic example for a future Launcher UI / Foundry Control Center entry point before any implementation.

## Problem statement

Foundry work currently requires repeated manual ChatGPT/Codex handoff and copy/paste across staging packets, planning notes, execution prompts, and PR summaries.

## Why this matters

Dobromir needs faster project initiation without losing governance, approval gates, packet-first source of truth, or clear execution boundaries.

## Current situation

Markdown packets and Codex prompts are manual. ChatGPT helps structure strategy and planning, Codex updates repository files, Linear may later mirror approved work, and GitHub records changes through PRs.

## Target situation

A future UI/control entry point guides intake, classification, parent context, planning depth, approval categories, execution permissions, and result handoff while producing packet-first outputs.

## Primary users / roles

- Dobromir as decision owner.
- ChatGPT as planning architect.
- Codex as execution agent.
- Linear as execution mirror.
- GitHub as change record.

## Affected systems / teams

- Foundry Launcher workflow.
- Foundry staging packets.
- Foundry planning pack templates.
- Future Foundry Control Center.
- Future Linear/Codex/GitHub integrations, if separately approved.

## Known constraints

- No automation before approval.
- No UI implementation in this packet.
- Packet remains source of truth.
- Linear issues must derive from approved scope.
- Codex execution remains blocked until execution-readiness allows it.
- Registry mutation remains blocked unless separately approved.

## Assumptions

- The future UI should remain selection-first and typing-light.
- Free-text fields should remain dictation-friendly but not audio-storing.
- Larger projects may need progressive planning packs.
- Small work should not be forced through all packs.
