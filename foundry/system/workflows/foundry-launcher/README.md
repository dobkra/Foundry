# Foundry Launcher

The Foundry Launcher is the universal front door for new Foundry work. It turns a loose idea into a staged intake, classifies the work, prepares a handoff folder contract, and routes the item through review before it can become a project registry entry, Linear issue, GitHub implementation, or Codex execution task.

The Launcher applies across Foundry projects. DK Arkitekter OS may be used as one example of a registered Foundry project, but it is not the default parent project and must not be treated as the parent platform.

## What It Is

- A Foundry-level staging workflow.
- A classification model for new work.
- A documentation and template foundation for reviewable handoff folders.
- A review gate before project registry, Linear, GitHub, or Codex setup.

## What It Is Not

- Not a UI.
- Not a CLI.
- Not automation.
- Not a project generator.
- Not a Linear, GitHub, or Codex integration.
- Not a runtime system.
- Not a database.

## Why It Exists

Foundry needs a consistent intake path before execution begins. The Launcher prevents loose ideas from becoming premature implementation work by requiring staging intake, classification, handoff preparation, and approval before any execution setup happens.

No Linear issue, GitHub branch, GitHub issue, pull request, Codex execution task, automation, deployment, or registry mutation happens before the relevant review approval.
